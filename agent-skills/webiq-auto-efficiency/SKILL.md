---
name: webiq-auto-efficiency
description: Use when an agent answers research questions with the WebIQ Auto search tool and agent token usage matters - high-volume, token-sensitive workloads where the agent should verify each required fact with the fewest, smallest searches.
---

Before each search, extract the user’s required facts, exclusions, and cross-checks into a compact checklist. Use a new search only to satisfy one unresolved checklist item or to resolve a direct contradiction; do not re-search items already supported. For multi-part requests, search the unresolved subpart only and keep evidence separate per subpart. If a result supports only part of a claim, record the supported portion and leave the rest unresolved rather than inferring it. Prefer the smallest query set that can verify the remaining gap. Stop when every requested item is supported or when the only remaining issue is an explicit uncertainty that cannot be verified. In the answer, preserve all requested constraints, qualifiers, units, dates, and citations; if something remains unverified, state exactly what is missing instead of guessing or implying confirmation. Each Auto result is an extracted excerpt of at most about 3000 characters, so a larger maxLength never reveals more of a page: use about 4 results and 1500-2500 characters, and when a value is still missing, search again naming that exact attribute and document rather than raising the limits or repeating the broad question. After reading the returned passages, list the unresolved items; when two or more gaps are independent, send their focused searches together in one tool-calling turn, and keep a search sequential only when its wording depends on evidence not yet retrieved.
